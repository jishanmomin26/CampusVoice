# CampusVoice — Database Architecture & Migrations

Relational persistence layer, schema declarations, and version-controlled migrations for the **CampusVoice** platform.

---

## 1. Overview

CampusVoice uses **PostgreSQL** as its primary relational database management system. Relational persistence guarantees ACID compliance, transactional integrity across feedback analysis writes, and secure storage for administrative user identities.

* **Database Engine**: PostgreSQL 18+ (Local) / Neon PostgreSQL (Production)
* **ORM**: SQLAlchemy 2.x
* **Driver**: psycopg3 (`psycopg[binary]`)
* **Migration Framework**: Alembic
* **Migration Script Location**: `backend/alembic/versions/`

---

## 2. Schema Architecture

### A. `feedback` Table
Stores raw student submissions and the enriched intelligence outputs generated by the ML pipeline:

| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | `PRIMARY KEY`, `AUTOINCREMENT` | Unique feedback record identifier. |
| `department` | `VARCHAR(100)` | `NULLABLE` | Academic department (e.g., Computer Science). |
| `semester` | `VARCHAR(50)` | `NULLABLE` | Academic semester (e.g., Fall 2026). |
| `feedback_text` | `TEXT` | `NOT NULL` | Raw student feedback comment. |
| `clean_text` | `TEXT` | `NULLABLE` | Preprocessed, normalized, and lemmatized text. |
| `sentiment_label` | `INTEGER` | `NULLABLE` | Numeric sentiment class: `-1` (Negative), `0` (Neutral), `1` (Positive). |
| `sentiment_score` | `VARCHAR(50)` | `NULLABLE` | Textual sentiment name (`negative`, `neutral`, `positive`). |
| `sentiment_confidence` | `FLOAT` | `NULLABLE` | Model confidence probability ($0.0 \le p \le 1.0$). |
| `category_label` | `VARCHAR(100)` | `NULLABLE` | Predicted feedback category name. |
| `category_confidence` | `FLOAT` | `NULLABLE` | Category prediction confidence probability ($0.0 \le p \le 1.0$). |
| `priority_score` | `INTEGER` | `NULLABLE` | Deterministic priority score ($0 \le s \le 100$). |
| `priority_level` | `VARCHAR(50)` | `NULLABLE` | Administrative priority tier (`High`, `Medium`, `Low`). |
| `priority_reason` | `TEXT` | `NULLABLE` | Transparent explanation of priority score assignment. |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT now()`, `NOT NULL` | Timestamp of submission creation. |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT now()`, `NOT NULL` | Timestamp of last modification. |

### B. `users` Table
Stores user accounts, credentials, and role authorizations for JWT authentication and RBAC:

| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | `PRIMARY KEY`, `AUTOINCREMENT` | Unique user identifier. |
| `username` | `VARCHAR(100)` | `NOT NULL`, `UNIQUE` | Case-insensitive unique username. |
| `password_hash` | `VARCHAR(255)` | `NOT NULL` | Salted bcrypt password hash (12 rounds). |
| `role` | `VARCHAR(50)` | `NOT NULL`, `DEFAULT 'student'` | Authorization role (`student` or `admin`). |
| `is_active` | `BOOLEAN` | `NOT NULL`, `DEFAULT true` | Account activation flag. |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT now()`, `NOT NULL` | Account registration timestamp. |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT now()`, `NOT NULL` | Account update timestamp. |

## 3. Migration History (Alembic)

Database schema revisions are managed using Alembic. Migration scripts reside in `backend/alembic/versions/`:

1. **`001_create_feedback`** (`001_create_feedback_table.py`):
   * Creates the foundational `feedback` table with `id`, `department`, `semester`, `feedback_text`, and timestamp columns.
2. **`002_add_analysis_fields`** (`002_add_analysis_fields_to_feedback.py`):
   * Expands `feedback` with nine ML intelligence columns (`clean_text`, `sentiment_label`, `sentiment_score`, `sentiment_confidence`, `category_label`, `category_confidence`, `priority_score`, `priority_level`, `priority_reason`).
   * Relaxes `department` and `semester` to `nullable=True` to support direct text submissions through the web portal.
3. **`003_create_users`** (`003_create_users_table.py`):
   * Creates the `users` table for user management, bcrypt credentials, and role-based access control.

## 4. Migration Execution Commands

From the `backend/` directory:

```bash
# Apply all pending migrations to the database
alembic upgrade head

# Roll back the latest migration
alembic downgrade -1

# Show current database migration revision
alembic current

# Display revision history
alembic history
```

## 5. Local Database Setup

### Local PostgreSQL:
1. Ensure PostgreSQL is installed and running on port 5432.
2. Create a database named `campusvoice`:
   ```sql
   CREATE DATABASE campusvoice;
   ```
3. Configure `backend/.env`:
   ```env
   DATABASE_URL=postgresql+psycopg://postgres:YOUR_PASSWORD@localhost:5432/campusvoice
   ```
4. Run migrations:
   ```bash
   cd backend
   alembic upgrade head
   ```

## 6. Production Database Setup (Neon PostgreSQL)

CampusVoice uses **Neon PostgreSQL** (Serverless PostgreSQL) in production:

* **Connection Security**: SSL mode is strictly required (`sslmode=require`).
* **Connection Pooling**: Neon provides high-concurrency connection pooling compatible with SQLAlchemy connection pool managers.
* **Production Connection URL Format**:
  ```env
  DATABASE_URL=postgresql+psycopg://<user>:<password>@<neon-host>.neon.tech/<dbname>?sslmode=require
  ```
* **Credential Safety**: Connection credentials are configured exclusively as environment variables in the Render backend hosting dashboard and are never committed to version control.
